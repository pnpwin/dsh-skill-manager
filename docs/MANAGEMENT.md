# Управление экземплярами скиллов

Начиная с 0.3.0 действия находятся в подробностях **выбранного экземпляра**, а не всей группы по имени. Раскройте имя → **Открыть этот экземпляр**. Допустимость проверяется сервером повторно перед изменением: название источника `custom` само по себе не разрешает менять файлы.

## Доступные действия

| Экземпляр | Рабочий статус | Действие с файлами |
|---|---|---|
| Управляемый локальный filesystem-скилл | Включить / выключить | Архивировать / восстановить / удалить навсегда |
| Bundled, plugin, runtime/provider-скилл | Включить / выключить ограничение менеджера | Файлы защищены; архивации и удаления нет |
| Неоднозначная synthetic-запись, неподдерживаемый runtime или операция с неизвестным исходом | Ограничение с пояснением | Запрещено до проверки/восстановления |

Кнопки зависят от текущего состояния. После архивации доступны восстановление и удаление архивной копии; после окончательного удаления остаются история и счётчики, но не кнопка восстановления. Для большого/ссылочного набора ресурсов безопасное управление инструкцией может оставаться доступным отдельно от запрещённых операций со всем каталогом.

## Подтверждение

1. Нажмите действие. На этом шаге сервер только проверяет цель и подготавливает короткоживущий план — файлы и политика ещё не меняются.
2. Проверьте точный экземпляр, цель, область действия, число файлов/байтов и предупреждения.
3. Нажмите **Подтвердить**. Для удаления дополнительно введите имя точно как показано; пробелы и регистр не исправляются автоматически.
4. Дождитесь результата и обновления каталога. Показанная кнопка не заменяет серверную проверку прав, версии файла и назначения.

План истекает через две минуты по умолчанию. При изменении определения/файлов или занятом месте восстановления потребуется новый план. Двойное выполнение одного подтверждения не повторяет действие. Браузеру не разрешено подменить путь: запрос содержит только ID/действие, затем непрозрачный токен и, при удалении, подтверждаемый текст.

## Включение и выключение

### Локальный файл

Для поддерживаемого filesystem provider выключение записывает в YAML frontmatter инструкции `disable-model-invocation: true` и `user-invocable: false`. Тело инструкции, прочие метаданные и комментарии сохраняются. Включение после выключения менеджером восстанавливает сохранённые исходные флаги: пользовательский-only скилл не превращается без причины в разрешённый модели. Явное включение ранее внешне выключенного файла без сохранённой политики устанавливает разрешённые флаги обеих поверхностей.

Один разрешённый способ вызова уже означает рабочий статус «включён». Файловые провайдеры с нестандартным именем должны быть явно перечислены администратором в `additionalFilesystemProviders`; иначе менеджер не предполагает, что редактирование этих YAML-флагов будет ими учтено.

### Bundled/plugin и другие защищённые определения

Менеджер хранит **профильное переопределение запрета**, не редактируя `node_modules`, `app.asar`, пакетные инструкции или конфигурацию поставщика. Выключение блокирует новые вызовы модельного `skill`, вложенные PTC-вызовы и пользовательскую загрузку `/skill-name`. Нейтральные метаданные экземпляра остаются в каталоге менеджера.

Включение **снимает только запрет менеджера**, возвращая исходную политику поставщика. Оно не разрешает вызов, который поставщик сам запрещает. Это не выключение всего плагина и не удаление его других инструментов.

Запрет применяется к каноническому экземпляру (provider/name/расположение), не ко всем одноимённым скиллам. Выигравшая проектная копия с другим ID не отключается вместе с bundled-копией. Изменение расположения при обновлении пакета может создать новый экземпляр: его нужно проверить отдельно, автоматического запрета всех будущих версий по имени нет.

Внутри активных агентов используются собственные scoped policy providers и executor guards через публичные API DSH. При неполном обнаружении или невозможности подтвердить применение новая затронутая операция отклоняется, а не молча пропускается. Менеджер нормализует только доказанно собственные policy summaries обратно к исходному provider перед учётом ID и статистики; чужие SDK-клиенты могут видеть policy provider как источник действующего ограничения.

Переопределение действует, **пока включён сам менеджер**. При его выгрузке собственные регистрации снимаются; сохранённые запреты восстанавливаются после повторного запуска. Исходные файловые YAML-флаги, напротив, остаются в инструкции независимо от менеджера.

### Общие ограничения

Уже загруженные инструкции не удаляются из истории и памяти активной беседы. Запрет новых `skill`-загрузок не является файловой песочницей: он не запрещает произвольный `read` доступного файла и не останавливает уже запущенный скрипт. При выключенном watcher filesystem provider его каталог может требовать обновления/перезапуска DSH. Несколько каталожных записей, указывающих на один физический файл, увидят одни и те же изменения этого файла.

## Архивирование и возврат

Для уверенно распознанного bundle (`<имя>/SKILL.md` с совпадающей базой ресурсов) перемещается весь каталог, включая ресурсы. Для плоской `.md`-инструкции или неоднозначной границы каталога перемещается только инструкция; общие соседние ресурсы не затрагиваются. План показывает эту разницу до подтверждения.

Архив размещается на той же файловой системе, рядом с исходной целью, внутри `.dsh-skill-manager-archive/<id>/<operationId>/payload`. Обычное одноуровневое обнаружение DSH его не находит. Не добавляйте внутренние каталоги архива в `customSkillDirs`. Менеджер не меняет Git ignore: если скиллы находятся в проекте, учитывайте архивные файлы при проверке Git status.

Возврат сохраняет исходный путь и канонический ID, никогда не затирает занятое назначение. Для каталога назначение резервируется эксклюзивно, содержимое публикуется с журналом фаз; это не атомарная транзакция всей файловой системы. Не вызывайте скилл до успешного завершения. Незавершённые управляемые операции временно запрещают новые skill-загрузки данного экземпляра через политику менеджера.

Символические/жёсткие ссылки, специальные файлы, пакетные ресурсы и превышение лимитов могут запретить файловое действие. Ошибка другого диска/mountpoint не обходится скрытым копированием с последующим удалением источника. Переезд вне архива обычным файловым инструментом не является manager restore и может создать новый ID.

## Окончательное удаление

Удаляется только показанная в плане физическая цель. Сначала она захватывается в приватный карантин на той же файловой системе, повторно проверяется, затем очищается после сохранения подтверждённого намерения. Исходный путь не передаётся в слепое рекурсивное удаление. Если удаляется архивная копия, позднее созданный файл на прежнем пути не затрагивается.

Операция необратима после успешной очистки. SQLite-история, алиасы и записанные вызовы не удаляются. Архив — механизм возврата, не резервная копия от потери диска; перед массовой ручной работой сделайте отдельный backup.

## Неизвестный результат и восстановление

Смена экземпляра, закрытие страницы или timeout отменяют ожидание интерфейса, **не доказывают отмену уже принятого действия**. Не повторяйте выполнение. Используйте **Проверить состояние**: это чтение receipt по ID операции и обновление каталога, не новая мутация. Незавершённый/неизвестный исход остаётся заблокированным; истёкший, ещё не принятый план не сможет начать выполнение позднее.

`recovery-required` означает, что после сохранения намерения не удалось подтвердить завершение. Менеджер сохраняет доступные исходные/карантинные байты, не угадывает успех и не запускает автоматическую очистку при рестарте. Не удаляйте скрытый архив и не обнуляйте SQLite. Остановите операции, сохраните согласованный backup базы и уцелевших файлов, затем сопоставьте журнал с реальным состоянием. Автоматической кнопки «принудительно завершить» нет.

Токены подтверждения живут только в памяти сервера/интерфейса, не записываются в SQLite, Session, localStorage или журнал действий. Публичный `operationId` не является токеном и не разрешает выполнение.

## Доступ для агентов и других плагинов

Agent tool `skill_manager` и Cordis API v1 остаются **read/refresh-only**. Они могут читать `management`, историю и результаты, но не выдают подтверждения и не меняют файлы. Изменения проходят отдельные точные owner-authenticated HTTP-маршруты существующего DSH connection; дополнительных серверов и credential bindings нет. [Описание API](API.md).
