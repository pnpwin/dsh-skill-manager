# Обновление до 0.3

## Данные

SQLite v2 автоматически получает таблицу `file_controls` и монотонную версию схемы **3**. Идентичность остаётся `identityVersion: 2`: ID экземпляров, aliases, исходные event keys, записанные вызовы, scope memberships и начало покрытия не переписываются. Из v1 сначала выполняется [миграция идентичности](upgrade-0.2.md).

Новая таблица хранит исходные invocation-флаги локальных инструкций, размещение архива, фазы незавершённых действий и запреты менеджера для provider-скиллов. Тела инструкций и секретные токены подтверждения в SQLite не сохраняются. Никакие реальные скиллы не выключаются, не перемещаются и не удаляются автоматически при обновлении; действия требуют отдельного owner-подтверждения.

Перед заменой остановите старый writer или используйте Plugin Manager, который выгружает текущий bundle. Сохраните согласованную SQLite backup-копию. Версия 0.2 не откроет схему 3: для downgrade необходимы заранее сохранённая база и согласованное состояние внешних файлов/архивов. Не запускайте старый и новый writer одновременно.

## API и интерфейс

Cordis service и agent tool остаются read/refresh-only, API v1. Добавлены необязательный `SkillRecord.management` и уведомление `type: 'management'`. К существующим owner HTTP-маршрутам добавлены prepare/execute/status; они не открываются agent tool.

В подробностях выбранного экземпляра появились **Рабочий статус** и **Действие с файлами**. Bundled/plugin разрешены только переключения через отдельную политику; пакетные файлы защищены. Локальные файлы могут иметь дополнительные операции в зависимости от подтверждённой границы каталога, ссылок, доступа и лимитов. [Инструкция](MANAGEMENT.md).

После установки обновите существующую страницу DSH, чтобы получить новый Client. Полный перезапуск Host нужен только если Plugin Manager сообщает `restart-required` или ошибку применения. Результат `applied` подтверждает активацию Host, но сам по себе не является проверкой браузерного рендера.

## Зависимости и сборка

Добавлен чистый JS parser `yaml` 2.9.0 (ISC) для корректного редактирования frontmatter без ручной обработки YAML. Пакет по-прежнему native ESM, без install/prepare/prepack hooks. Перед публикацией выполняются тесты, явная проверка сборки/ресурсов и API declarations. SDK integration tests требуют built reference DSH; вне рабочего дерева их можно включить через `DSH_REFERENCE_ROOT`, без него они явно пропускаются, а не имитируют реальную композицию.
